# 更新器自动接入脚本

适用：Windows PowerShell 5.1 或 PowerShell 7，已安装 .NET 10 SDK，SDK 风格的 .NET 10 WinForms 项目。WPF、旧 .NET Framework、多目标项目、中央包版本管理或自定义编译列表暂不自动处理，不会替同事升级框架。

## 最短操作
解压整个工具包，在工具包目录打开 PowerShell：

```powershell
.\Install-Updater.ps1 -Project "D:\Projects\ProductA\ProductA.csproj" -AppId "Company.ProductA" -ManifestUrl "https://你的更新服务器/product-a/update.json" -DownloadPrefix "https://你的更新服务器/product-a/"
```

将参数替换成真实值。AppId 每个产品唯一，跨版本保持一致；DownloadPrefix 以 / 结尾。脚本只配置项目，不会创建更新服务器，也不会替项目发布新版本。

随后在主窗口构造函数的 InitializeComponent(); 后加一行：

```csharp
TeamUpdaterBootstrap.Attach(this);
```

编译运行即可看到右上角“更新 / 回退”按钮。请检查按钮是否遮挡现有控件，必要时在生成代码中调整位置。不要在多个窗口重复接入。调用需早于主窗口 Shown 事件。

## 预览与撤销
原命令追加 `-WhatIf` 可先查看操作，不写文件。

```powershell
.\Install-Updater.ps1 -Project "D:\Projects\ProductA\ProductA.csproj" -Uninstall
```

撤销后手动删除之前添加的 Attach 行。如果项目或生成文件已被同事改过，脚本拒绝覆盖；请自行合并处理。手动撤销需去掉 csproj 内两个 Label="TeamUpdaterAutoSetup" 的 XML 组，并移除生成目录及 Attach 行。

## 自动处理内容
- 原 csproj 备份，添加 NuGet 引用。
- 将包随项目保存在 TeamUpdater.Generated 中，并添加项目专用本地包源，不替换原 NuGet 配置。
- 生成 JSON 配置、按钮与历史注册代码。
- 将配置复制到构建和发布目录。
- 重复安装检查与撤销前哈希检查。

提交时应包含 TeamUpdater.Generated 下的包、源码和配置，否则同事或 CI 无法恢复引用。install-state.json 和 project.original 用于本地撤销，可不提交；克隆到其他路径后不要复用原机器的撤销记录。对于已有配置的项目，编辑 updater-settings.json 即可更换地址，但之后自动撤销会拒绝覆盖修改。

## 首次发布验收
运行 `dotnet build`，检查按钮。以自包含 Windows 发布，更新 ZIP 根目录放 EXE 和依赖；更新清单必须包含 version、url、sha256。程序版本来自程序集版本，发布时务必增加 Version，并确保清单一致。
先发布旧版本 A、运行一次记录历史，再发布 B，验证升级和回退。原目录不能删除；回退不恢复数据库。当前不带固定启动器、数字签名及启动失败自动回退。

企业执行策略若阻止脚本，请按公司流程审核签名或由 IT 放行；无需管理员权限，不建议全局关闭执行策略。
