# 团队更新器安装向导
完整解压，运行 TeamUpdaterSetup.exe。向导本身不要求预装 .NET；目标项目开发需要 .NET 10 SDK。

流程：欢迎 → 选择 .csproj → 确认 → 安装 → 完成。
当前支持 net10.0-windows WinForms。会自动生成 AppId、备份项目、接入 NuGet 和生成配置。完成后在主窗口 InitializeComponent(); 后添加 TeamUpdaterBootstrap.Attach(this);，然后编译并检查按钮位置。

管理员统一配置
把 team-profile.example.json 复制为 team-profile.json，填入公司真实 HTTPS 更新根地址，与 EXE 放在一起再分发。每个项目的地址为 根地址/自动生成的产品标识/update.json。普通同事不必输入任何地址。
没有真实服务器配置时也可以接入项目，但显示待配置，不会产生可用的在线更新服务。既有项目再次安装保留原设置；要迁移服务器请编辑该项目的 updater-settings.json。

发布模板
templates 下提供 GitLab Windows Runner 打包模板，需要管理员将占位项目路径改为真实路径，再合入现有 CI。模板生成包和清单作为 artifacts，不会上传到尚未确定的生产服务器。管理员需在 CI 中将 ZIP 先上传，再将 update.json 发布到产品目录；认证由 GitLab CI Secret 管理。这里不默认某一种云存储。

限制
手动回退；无固定启动器、数据库恢复和独立数字签名。自动接入不修改业务代码；一个 Attach 调用需要同事确认主窗口。安装前备份和手动撤销说明在 TeamUpdater.Generated。目标项目重复接入会保留现有文件。不要把不同产品复制为相同 AppId。
